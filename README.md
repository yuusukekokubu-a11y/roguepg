# ローグ・パーティー（コマンドRPG × ローグライク）

企画書（`design/企画書.xlsx`）をもとにした、ブラウザで遊べるゲームです。
草原 → 氷雪地帯 → 火山 → 魔王の城の **全4層** を遊べます。魔王を倒せばクリアです。

> その場の出会いと拾い物で、毎回ちがうパーティーを組み上げる

## 遊ぶには

[Node.js](https://nodejs.org/)（JavaScript をパソコンで動かすためのソフト）の 20 以上が必要です。

```bash
npm install      # 必要な部品（ライブラリ）をダウンロード
npm run dev      # 開発用サーバーを起動
```

表示された `http://localhost:5173/` をブラウザで開くと遊べます。スマホ幅の画面にも対応しています。

| コマンド | やること |
| --- | --- |
| `npm run dev` | 開発用サーバーを起動（ファイルを保存すると自動で画面が更新される） |
| `npm run build` | 公開用のファイルを `dist/` に作る（そのままWebサーバーに置けば遊べる） |
| `npm test` | 自動テストを実行（データの読み取り・戦闘ルール・バランス） |
| `npm run import-data` | 企画書（Excel）からゲームデータを作り直す |

## 使っている技術（用語の説明つき）

- **TypeScript**：JavaScript に「型」（データの形のチェック）を足した言語。書きまちがいを実行前に見つけてくれる
- **Vite**：開発用サーバーと、公開用ファイルを作る道具（ビルドツール）
- **Vitest**：自動テストの道具。`tests/` のテストを実行する
- **ExcelJS**：Excel ファイルを読む部品。企画書からデータを取り出すのに使う
- 画面は React などのフレームワーク（画面作りの部品集）を使わず、素の HTML/CSS で作っている

## 見た目（デザイン）

- **黒鉄の窓 × くすんだ真鍮の枠 × ドット文字**（フォントは DotGothic16）。色は `src/style.css` の先頭にまとめている
- **戦闘の演出**：ダメージ・回復の数字が浮かぶ／技の名前が出る／行動したキャラが動く／倒れた敵が沈んで消える。自分の番になった直後（0.35秒）と戦闘が終わった直後（0.9秒）はコマンドを受け付けず、連打での押し間違いを防ぐ（`src/ui/screens/battle.ts`）
- **マップ・報酬の演出**：画面の切り替えはふわっと表示（直後0.25秒はタップを受け付けない）。マップは選んだマスが光り道をなぞってから移動、層に入ると層の名前を表示。報酬は経験値・お金を数え上げ、カードを1枚ずつ配り、選んだカードが光って持ち物へ入る
- **持ち物は種類ごと**（どうぐ／本／装備／アクセサリー）に見出しを付けて並べ、上のタブで絞り込める。同じ物は「×2」とまとめる（`src/ui/inventory.ts`。パーティー画面・報酬画面・ショップの「売る」で共通）
- **どの画面もスマホ1画面に収まる**。長い一覧（持ち物・ショップなど）だけ、窓の中でスクロールする
- **絵はすべて自作のドット絵**。画像ファイルは使わず、文字で描いた設計図をプログラムで画像にしている
  - `art/art_jobs.mjs`・`art/art_enemies.mjs`：14職業と敵52体の設計図（`'.'` は透明、ほかの文字がパレットの色。輪郭線は自動で付く）
  - `art/art_icons.mjs`：地図のマス・持ち物などのアイコン
  - 設計図を直したら `npm run build-art` で `src/ui/pixel/sprites.ts`・`icons.ts` を作り直す（この2つは自動生成なので直接編集しない）
  - `src/ui/pixel/backgrounds.ts`：4層の背景（黄昏の草原・夜の雪原・火山・魔王の城）

## 企画書とデータのつながり（データ駆動）

スキルブック・アクセサリー・アイテム・職業などは、**企画書の Excel が正本（おおもと）** です。

1. `design/企画書.xlsx` を編集する（例：「スキルブック」シートに1行足す）
2. `npm run import-data` を実行 → `src/data/generated/*.json` が更新される
3. ゲームに反映される

スキルブックの「効果」欄の文章（例：`物理ダメージ中＋防御ダウン`）は、プログラムが自動で「部品」に分解して使います（`src/engine/parser.ts`）。
企画書の「部品」シートにある言い回しなら、新しい本を足すだけで動きます。知らない言い回しがあると `npm test` でエラーになって教えてくれます。

例外として、次のものはプログラム側に書いています。

| データ | 場所 | 理由 |
| --- | --- | --- |
| アクセサリーの効果の中身 | `src/data/accessoryMods.ts` | 効果が多彩なため、名前ごとに部品を対応づけている |
| 敵の数値・行動 | `src/data/enemies.ts` | 企画書に数値がないため（技の文章は本と同じ書き方） |
| 武器・防具 | `src/data/equipment.ts` | 企画書に一覧がないため新規作成 |
| イベント | `src/data/events/` | 企画書に一覧がないため新規作成 |

## イベント

マップの「❓」マスで起きるイベントは、4種類・全40個あります（`src/data/events/`）。

| 種類 | 数 | 起きる条件 | ファイル |
| --- | --- | --- | --- |
| 💞 ペアイベント | 12 | 特定の2職業がパーティーにそろっている | `pairs.ts` |
| ⭐ 職業イベント | 14 | その職業がパーティーにいる（全職業に1つずつ） | `jobs.ts` |
| 🗺️ 層イベント | 8 | その層にいる（各層2つ） | `floors.ts` |
| いつでも | 6 | いつでも | `general.ts` |

- 出やすさは **ペア ＞ 職業 ＞ 層 ＞ いつでも**（重み 5 : 3 : 2.5 : 1）。`src/engine/events.ts` の `WEIGHT` で変えられる
- 1回のランで同じイベントは二度起きない
- 報酬には「能力値が永久に上がる」もある（キャラクターの `bonus`）

新しいイベントは、上のファイルに1つ足すだけで増やせます。回復・お金・本・装備・永続強化・戦闘などの部品は `src/engine/eventKit.ts` にあります。
足したら `npm test` を実行すると、全イベントの全選択肢が実際に動くかを確かめてくれます。

## 選ぶ楽しさのしくみ

- **報酬は3択**：戦闘・宝箱で手に入る物は、3つの候補から1つを選ぶ（「取らない」も可）。お金と経験値はそのまま入る
  - 普通の戦闘：本・アイテム・装備・アクセサリーから3つ（目利きの眼鏡を着けていると4つ）
  - 強敵：「本・装備・アイテム」の3択＋アクセサリー2択
  - ボス：本3択（★が出やすい）＋アクセサリー3択
- **敵の行動予告**：敵の頭の上に「次に何をするか」（攻撃→誰、全体攻撃、溜め、強化、回復など）が出る。予告を見て、守る・溜めを崩す・先に倒すを決める
- **変異個体**：普通の敵が、ときどき「狂暴な」「硬化した」「俊敏な」「再生する」「毒をまとう」「巨大な」のどれかになって出る（色・大きさが変わる）。強いぶん経験値・お金が1.5倍（`src/data/variants.ts`）
- **敵の種類**：52体（企画書の36体＋各層4体の追加）。敵の組み合わせは各層13〜16通り
- **休憩所**：「休む（HP・MP 40%回復）」か「鍛える（1人の能力値がずっと上がる）」のどちらか1つ
- **ショップのサービス**：「技を忘れさせる（15G×層）」「本の取り寄せ（職業を指定すると、その職業の本が3冊届き1冊選べる。1店につき1回）」

## バランス調整

「試作で調整」の数値は、ほぼすべて **`src/engine/balance.ts`** に集めてあります（◎○△×の数値化、技の威力、MP消費、状態異常のダメージ、持ち物の上限、値段など）。
マップのマス数・出現率は `src/engine/map.ts` の `MAP_CONFIG` です。

`npm test` を実行すると、コンピューターが各職業で40回ずつ自動で遊び、各層への到達率とクリア率を表示します（技を半分ランダムに選ぶ素朴なAIなので、人が遊べばもっと勝てます）。

層ごとに調整したいときは、その層の開始時点を想定したパーティー（人数・レベル・装備）で、その層だけを遊ばせる測定も使えます。

```bash
FLOOR_SIM=1 npx vitest run tests/floor-balance.test.ts
```

いまの目安（自動プレイ、各職業80回）。職業ごとのクリア率はおよそ10〜48%（回復役の白魔道士が一番高く、補助技の多い盗賊が一番低い。補助技はこのAIでは活かしきれないため、人が遊ぶと差はもっと小さいはず）：

| | 2層到達 | 3層到達 | 4層到達 | クリア |
| --- | --- | --- | --- | --- |
| 全職業の平均 | 93% | 54% | 32% | 22% |

## 企画書から変えた点

遊んでみての提案で、企画書から次の点を変えています（Excel の企画書はまだ直していません）。

| 項目 | 企画書 | いまの実装 |
| --- | --- | --- |
| 最初のパーティー | 主人公ソロ（1層は敵を弱めに） | **2人**。主人公のあと、ランダムな3人の候補から相棒を1人選ぶ |
| 層クリア時 | 毎回、仲間を1人選ぶ | 1・2層クリアで仲間を選ぶ（3人→4人）。**3層クリアでは「加護」を3つから1つ選ぶ** |
| MPの回復 | 休憩所・アイテム・魔法 | ＋「たたかう」を当てるとMPがたまる |
| 職業の特性 | なし（主人公にも補正なし） | **全職業に「特性」**（いつも効く固有能力）を1つずつ。職業ごとの強さの差を縮めるため、弱い職業ほど強め |
| 本の数 | 210冊 | 回復手段のない5職業に1冊ずつ追加して215冊（侍「残心」・黒魔道士「魔力吸収」・呪術師「厄払い」・盗賊「手当て」・狩人「薬草の知恵」） |

**加護**（`src/data/blessings.ts`）：パーティー全員に、ランの最後まで効く恩恵。8種類からランダムに3つ出る。
勇者（攻撃・魔力+20%）／守護（受けるダメージ-15%）／疾風（素早さ+15%）／癒し（毎ターンHP5%回復）／魔力（戦闘後MP25%回復）／浄化（状態異常にかかりにくい）／不屈（戦闘中1回HP1で耐える）／再起（勝利後に倒れた仲間がHP30%で復活）

**職業の特性**（`src/data/jobTraits.ts`。追加の本も同じファイル）：
戦士＝闘志（受けるダメージ-8%、被弾で攻撃アップ）／騎士＝守護者（受けるダメージ-15%、毎ターンHP3%回復）／暗黒騎士＝血の渇き（物理攻撃で吸収）／侍＝不退転（戦闘中1回HP1で耐える）／白魔道士＝清らかな心（状態異常にかかりにくい）／黒魔道士＝魔力の泉（魔力+10%、勝利後MP30%回復）／赤魔道士＝器用（勝利後MP10%回復）／呪術師＝呪いの心得（受けるダメージ-10%、状態異常に強く、かけた状態異常が長持ち）／盗賊＝身軽（必ず先手、回避+20%、攻撃+10%）／狩人＝狩りの本能（倒すと次の番が早い、回避+8%）／錬金術師＝調合上手（回復量+15%）／吟遊詩人＝響く声（強化+15%）／踊り子＝華麗な足さばき（回避+10%）／召喚士＝契約の守り（受けるダメージ-10%、勝利後MP15%回復）

## 企画書で決まっていなかった点の「仮決め」

企画書で「保留」「試作で調整」になっていた点は、次のように仮で決めています。どれもあとで変えられます。

| 項目 | 仮決め | 変える場所 |
| --- | --- | --- |
| 1層あたりのマス数 | 10段＋ボス。分かれ道は4本 | `map.ts` |
| マスの出現率 | 戦闘46・イベント20・強敵10・休憩所10・ショップ8（中間の段は必ず宝箱、ボス直前は必ず休憩所） | `map.ts` |
| 持ち物の上限 | アイテム・本・装備を**まとめて12個**（装備中の物は数えない） | `balance.ts` |
| スキル枠 | Lv1で2枠、Lv3・5・8・12で1枠ずつ増える（最大6） | `balance.ts` |
| 最初の技 | 職業を選んだあと、3つの方向性の最初の本から1冊を選ぶ（企画書にない追加） | `run.ts` |
| 休憩所 | 休む＝HP・MPを最大の40%回復、戦闘不能も40%で復活。鍛える＝攻撃・防御・魔力・精神は層+1、素早さは層の半分（切り上げ）、HPは層×3+2 | `balance.ts`・`run.ts` |
| MPの回復手段 | 「たたかう」を敵に当てると最大MPの12%（最低2）たまる（外れたら0）。殴ってためて技を撃つ流れを作るため | `balance.ts` の `attackMp` |
| 「数ターン」 | 3ターン（強化・弱体は4ターン）。ターンはそのキャラが行動するたびに減る | `balance.ts` |
| 状態異常 | 毒＝毎ターン最大HPの6%×重ねた数（最大5重）／やけど＝7%＋攻撃力25%ダウン／混乱＝2ターン／スタン＝次の1回休み（溜め中なら溜めが崩れる） | `balance.ts` |
| 「状態異常の数だけ威力アップ」 | 状態異常の種類に加えて、ステータスダウンの数も数える（呪術師の弱体型と組み合わせやすく） | `battle.ts` |
| 召喚士「身代わりの獣」 | 召喚士本人が対象をかばう扱い | `battle.ts` |
| 魔法系・支援系の武器 | 杖・竪琴などにも攻撃力を付けた（ソロの1層で通常攻撃が弱すぎたため） | `equipment.ts` |
| 加入する仲間の装備 | 加入する層に合わせた段階の武器・防具を持ってくる | `run.ts` |
| 敵の数値・行動 | 名前・特徴・耐性・弱点は企画書どおり。数値は自動プレイで調整した仮の値。全体の難しさは層ごとの倍率（`enemyScale`）と、2層以降のボスだけの倍率（`bossScale`）でまとめて調整できる | `enemies.ts`・`balance.ts` |
| 弱体の下限 | ステータスは弱体を重ねても半分まで（氷の女王の吹雪で動けなくなりすぎたため） | `balance.ts` |
| HP半分以下の変化 | 氷の女王＝連続行動、炎竜＝ブレスの溜めが早くなる、魔王＝第2段階（連続行動＋状態異常無効） | `enemies.ts` の `halfHp` |

## フォルダ構成

```
design/企画書.xlsx        企画書（データの正本）
scripts/import-xlsx.mjs   Excel → JSON 変換
src/data/                 ゲームデータ（generated/ は自動生成なので直接編集しない）
src/engine/               ゲームのルール（画面に依存しない部分）
  parser.ts               効果の文章を部品に分解
  battle.ts               戦闘システム
  character.ts            ステータス・レベルアップ
  map.ts                  分かれ道マップの生成
  run.ts                  ラン全体の進行（報酬・ショップ・仲間加入・セーブ）
  events.ts               イベントマス
  balance.ts              調整用の数値
  autoplay.ts             バランス確認用の自動プレイ
src/ui/                   画面
tests/                    自動テスト
```
